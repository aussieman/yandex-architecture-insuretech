# Задание 4. Проектирование продажи ОСАГО

## Описание задачи

Компания InsureTech планирует запустить новый продукт: онлайн-оформление ОСАГО. Пользовательский путь включает заполнение заявки с данными об автомобиле, после чего сервис запрашивает предложения от всех доступных страховых компаний. Требования:
- Предложения отображаются на экране пользователя сразу по мере поступления ответов (максимум 60 секунд ожидания).
- Пик нагрузки: до 2500 одновременных пользователей.
- Страховые компании предоставляют REST API: создание заявки и получение предложения.

## Архитектурные решения

### Общий подход
- Сохранён подход из предыдущих заданий для получения данных от страховых компаний.
- Выделен новый сервис `osago-aggregator` для взаимодействия со страховыми компаниями.
- Функциональность оформления ОСАГО остаётся в `core-app`.
- Введена event-driven интеграция через Kafka для асинхронной обработки.

### Компоненты системы

- **core-app**: Монолитное приложение (Kotlin, SpringBoot) для отображения продуктов, оформления страховок, включая ОСАГО.
- **osago-aggregator**: Сервис (Kotlin, SpringBoot) для интеграции со страховыми компаниями по ОСАГО. Хранит заявки в Redis (osago-cache).
- **InsureTech Web**: Веб-приложение (JavaScript, React) для пользовательского интерфейса.
- **Event Streaming Platform (Kafka)**: Шина событий для асинхронного взаимодействия (топики: product-updates, policy-created, settlement-requests, osago-offers).
- **Системы страховых компаний**: Внешние API для создания заявок и получения предложений ОСАГО.
- **Базы данных**: core-db (PostgreSQL), ins-comp-settlement-db (PostgreSQL), osago-cache (Redis).

### Интеграции

1. **Веб-приложение ↔ core-app**:
   - REST API для создания заявки на ОСАГО и получения тарифов (с Rate Limiting).
   - WebSocket для real-time отображения предложений ОСАГО по мере поступления.

2. **core-app ↔ osago-aggregator**:
   - REST API для создания заявки и получения предложений (с Retry, Timeout).

3. **osago-aggregator ↔ Системы страховых компаний**:
   - REST API для создания заявки и опроса предложений (с Circuit Breaker, Retry, Timeout).

4. **Event-Driven через Kafka**:
   - osago-aggregator публикует предложения в топик `osago-offers`.
   - core-app подписывается на `osago-offers` для получения обновлений.
   - core-app публикует `policy-created` при оформлении.
   - ins-comp-settlement подписывается на `policy-created` и `product-updates`.

### Паттерны отказоустойчивости

- **Rate Limiting**: На REST от веб-приложения к core-app для защиты от перегрузки.
- **Circuit Breaker**: На REST от osago-aggregator к страховым компаниям для предотвращения каскадных сбоев.
- **Retry**: На REST вызовах для повторных попыток при временных ошибках.
- **Timeout**: На всех внешних вызовах для ограничения времени ожидания (макс. 60 сек для предложений).

### Учёт множественных экземпляров

Сервисы развернуты в нескольких экземплярах:
- REST интеграции используют load balancer, что не зависит от количества экземпляров.
- Kafka обеспечивает масштабируемость и отказоустойчивость подписок/публикаций.
- Redis для osago-aggregator поддерживает распределённое хранение заявок.

## Диаграмма

Диаграмма контейнеров `InsureTech_C4_osago.xml` отражает все компоненты, интеграции и паттерны. Открыть в draw.io для просмотра.

## Реализация

- osago-aggregator: Асинхронно создаёт заявки во всех компаниях, опрашивает предложения каждые N секунд, публикует в Kafka.
- core-app: Принимает заявку, передаёт в osago-aggregator, подписывается на Kafka для обновлений, отправляет через WebSocket в веб.
- Веб: Отправляет заявку по REST, получает предложения по WebSocket для мгновенного отображения.</content>
